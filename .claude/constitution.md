# 技术章程

## 1. 用户价值优先

每个迭代都必须交付可演示、可验收的用户价值。不为未确认的未来需求预留复杂扩展点。

## 2. 单体优先

2C2G 单机是当前硬约束。系统采用模块化单体，只有在出现可量化的性能或团队边界问题时才讨论拆分服务。

## 3. 简单、可观测、可恢复

- 优先 Go 标准库和小而成熟的依赖。
- 网络服务提供健康检查；生产故障必须可从日志定位。
- 数据有持久化卷、定期备份和可演练的恢复流程。

## 4. 安全默认

- 密钥只通过环境变量或密钥管理注入，不进入代码库。
- 外部输入在边界处验证；SQL 必须参数化。
- 管理接口默认需要身份认证，最小权限分配。
- 依赖变更必须保留锁文件并通过 CI。

## 5. 测试是交付的一部分

- 核心业务规则用单元测试覆盖。
- HTTP 边界用处理器测试覆盖。
- 与 MySQL 方言或事务相关的行为使用真实 MySQL 集成测试。

## 6. 决策可追溯

重要技术决策以 ADR 记录背景、选项、结论和后果。代码变更必须可追溯到用户故事或 Bug。

## 7. 章程变更

修改本文档必须在 PR 中说明原因、影响和迁移方式。
