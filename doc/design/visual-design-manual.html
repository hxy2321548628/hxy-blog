设计系统 / 视觉设计手册
Visual system · 2026

简约，而不止于简单。

面向个人技术博客的视觉设计基线：让界面保持安静，让内容成为唯一主角；用清晰层级、克制反馈和细腻状态，建立长期可信的阅读体验。

适用：React SPA 覆盖：读者端 + 管理端 主题：浅色 / 深色 状态：提案，待确认
01 — DIRECTION

视觉方向

继承参考界面的低噪声、轻边界和渐进披露，将“工具效率”转译为博客的“阅读专注”。视觉克制不等于信息缺失，而是每个元素都有清晰优先级。

01 / CONTENT

内容先于容器

优先使用留白、排版与分隔线建立层级，避免给每一段内容套卡片。图片和文字拥有完整呼吸空间。

02 / RESTRAINT

蓝色只表达动作

强调色仅用于链接、焦点、当前状态与主操作；导航选中优先使用中性底色，避免页面到处发蓝。

03 / DETAIL

细节提供信任

上传进度、保存状态、键盘焦点、空状态与错误恢复均需明确。高级感来自完整状态，而不是装饰。

避免：大面积渐变、玻璃拟态、厚重阴影、过度圆角、连续入场动画，以及首页堆叠大量统计卡片。
02 — COLOR

色彩系统

中性色负责内容与结构，冷蓝色负责交互。深色模式采用三级表面而非机械反色，确保长时间阅读仍舒适。

03 — TYPOGRAPHY

07 — RESPONSIVE

响应式与交互

响应式不是同比缩小。移动端删除低价值并列信息、保持 44px 触控目标，将文章目录变为按需打开的浮层。

断点布局行为内容策略
≥ 1200px1120px 居中容器；首页双列侧栏展示简介、主题和近期状态
768–1199px内容边距 32px；侧栏缩窄或下沉导航仍为横向，减少次级入口
< 768px单列；边距 16–20px摘要缩短，隐藏非关键元数据
< 480px编辑器工具栏可横向滚动上传控件占满宽度，操作文字化
动效基线：悬停反馈 100–120ms，颜色/展开 180–220ms，对话框不超过 300ms；不使用 Hover 位移，并尊重 prefers-reduced-motion。
08 — ACCESSIBILITY

无障碍基线

目标遵循 WCAG 2.2 AA。无障碍不是发布前补丁，而是组件验收的一部分；键盘、屏幕阅读器和弱视用户应能完成完整发布与阅读路径。

  • 正文文字对比度不低于 4.5:1，大字不低于 3:1。
  • 所有纯图标按钮必须提供准确的可访问名称。
  • 键盘焦点使用 2px 强调色，并保留至少 2px 外间距。
  • 触控目标至少 44×44px，视觉图标可维持 16–20px。
  • 文章图片必须支持替代文本；装饰图使用空 alt。
  • 错误不能只依赖颜色，需包含原因与恢复方式。
  • 标题层级连续，页面仅有一个语义主标题。
  • 主题切换遵循系统偏好，并保存用户主动选择。
09 — HANDOFF

开发交付规则

MVP 不引入重量级 UI 框架。先实现设计令牌与少量基础组件，再由真实页面驱动扩展；不为尚未出现的组件建立抽象。

层级建议落点约束
设计令牌src/web/src/styles/tokens.css组件禁止直接写品牌色；优先使用语义变量
全局样式src/web/src/styles/global.css只包含 reset、排版、主题和可访问性基础
基础组件src/web/src/components/ui/由页面需求产生；支持 default / hover / focus / disabled / error
图片上传src/web/src/features/media/状态进入 Redux；文件对象与临时预览不做持久化
页面布局src/web/src/layouts/读者端与管理端可共享令牌，不强行共享布局结构
完成定义：组件通过键盘操作、浅深色、360px / 768px / 1440px 三档检查；页面无横向意外溢出；文字和状态不依赖图片才能理解。
