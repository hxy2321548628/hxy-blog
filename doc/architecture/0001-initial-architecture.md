# ADR-0001：初始技术架构

- 状态：已接受
- 日期：2026-09-29

## 背景

个人博客运行在 2 vCPU、2 GiB 内存的单台服务器上。当前优先级是快速交付、运维简单和数据可恢复，而不是水平扩展。

## 决策

- 使用单仓库管理 Go API、React Web 和部署配置。
- 后端使用模块化单体，HTTP、业务和持久化边界在包级别分离。
- 前端使用 React + TypeScript + Vite，生产产物为静态文件。
- 持久化使用 MySQL、`utf8mb4` 和 InnoDB；具体版本以用户现有镜像为准。
- 使用用户现有镜像和 Docker Compose 单机部署。
- 不引入 Kubernetes、消息队列和分布式缓存。

```text
Browser
   |
Reverse proxy (TLS/static files)
   |-- /api --> Go API --> MySQL
   `-- /*   --> React static assets
```

## 2C2G 资源策略

- MySQL 开发基线：256 MiB InnoDB buffer pool，最多 50 连接。
- Go 连接池初始上限建议为 10，空闲连接上限为 5；以压测数据调整。
- 不在生产服务器运行 Node.js 开发服务器，只部署构建后静态文件。
- 监控优先使用主机指标和结构化日志。

## 后果

优点是部署简单、资源占用可控、本地与 CI 一致。代价是数据库和应用共享单机故障域，因此必须优先实现异机备份和恢复演练。

## 重新评估条件

只有在监控数据证明持续超过单机资源、发布互相阻塞，或业务出现独立扩缩容需求时，才评估拆分服务或引入缓存。
