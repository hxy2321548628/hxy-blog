# Sprint 8 开发计划

- 日期：2026-10-10
- 状态：本地实现与可用页面验证完成；登录后的管理操作待人工验收
- Sprint 目标：为前端加入暗色模式，使阅读和内容管理在不同环境光线下都清晰可用。

## 目标与范围

- 在前端提供可用键盘操作的浅色/暗色切换入口，首次访问跟随系统偏好；手动选择保存到浏览器本地，刷新和路由切换后保持一致。
- 为公开文章列表、文章详情、技术内容，以及登录和管理页面提供暗色配色。保留当前公开页的瑞士风格与管理端现有布局。
- 同步处理浏览器原生表单、代码块、数学公式、Mermaid 图表、编辑预览、图片上传反馈和悬浮音乐控件的可读性。
- 维护浅色模式的现有视觉效果；切换不影响文章、登录或上传数据。

## 非目标

- 不修改 Go API、数据库 Schema、鉴权行为、部署配置或文章数据。
- 不新增 UI 框架、主题服务端同步、跨设备同步、定时切换或更多主题。
- 不重做页面布局、品牌视觉或文章内容中的图片颜色。

## 已确认范围与实现假设

- 用户已确认覆盖整个前端，包括公开页、登录页和管理页。
- 切换采用浅色/暗色两态；未主动选择时跟随系统，主动选择后优先使用本地保存的偏好。浏览器存储不可用时，当前页面仍可切换，但不保证刷新后保留。
- 切换入口沿用页面现有导航或页头，不增加独立设置页。暗色配色从现有语义色变量扩展，保留公开页的红色强调和管理端的暖色强调。

## 故事与验收标准

### 故事 1：选择与记住主题

- Given 没有保存选择且系统偏好为暗色或浅色，When 首次打开博客，Then 页面按系统偏好显示；系统偏好改变时，未手动选择的页面随之更新。
- Given 用户使用鼠标或键盘切换主题，When 浏览文章、进入管理页或刷新页面，Then 所有页面沿用同一选择，切换按钮有准确的可访问名称和可见焦点。
- Given 用户曾主动选择主题，When 系统偏好随后变化，Then 页面继续使用用户选择；本地存储不可用时切换仍在当前页面生效。

### 故事 2：暗色页面与技术内容

- Given 暗色主题，When 浏览文章列表和详情，Then 标题、元信息、分类、分页、大纲、链接、错误/空状态及音乐控件都清晰可辨，布局与浅色模式一致。
- Given 文章包含代码、数学公式、Mermaid 图表和图片，When 在两种主题间切换，Then 代码和图表文字、背景与边界可读，图表在当前主题下正确显示；图片保持原样。
- Given 暗色主题，When 登录、编辑文章、预览、上传图片或查看失败反馈，Then 表单内容、占位符、禁用态、焦点和反馈可辨认，不影响原有操作。
- Given 360px、768px 和 1440px 视口，When 检查两种主题，Then 页面没有因主题新增的横向溢出；正文文字达到 WCAG AA 的 4.5:1 对比度目标，大字及关键界面边界达到 3:1。

## 风险与依赖

- 本次仅涉及浏览器本地偏好，无数据迁移或 API/鉴权变更；主题值不包含敏感信息。
- 主题须在首屏渲染前初始化，避免刷新时出现明显的浅色闪烁；同时需考虑系统偏好变更和浏览器存储异常。
- 现有公开页与管理端使用不同色系，暗色令牌应分别定义，避免互相覆盖。Markdown 中的代码高亮与 Mermaid 使用第三方样式或渲染结果，需要逐项验证。
- 不新增运行时依赖，沿用现有 React、CSS 和浏览器 API；2C2G 服务端资源不受影响。

## 执行顺序与验证命令

1. 确认本计划范围后创建开发分支；先实现故事 1 的失败测试与最小逻辑。验证：主题初始化、系统偏好变化、手动选择和持久化测试。
2. 实现故事 2 的暗色令牌及必要的技术内容适配。验证：`npm --prefix src/web run test`，并人工检查 360px、768px、1440px 的浅色/暗色页面。
3. 检查变更范围并运行 `task check`；记录通过项、未验证项和视觉验收结果。
