# Sprint 5 开发计划

- 日期：2026-10-09
- 状态：已完成生产环境人工验收
- Sprint 目标：把已确认的瑞士风格原型用于真实文章列表与详情，在不改变现有内容能力的前提下发布。

## 目标与范围

- 目标用户：浏览文章列表、按分类和分页查找内容、阅读技术文章的访客。
- 按 [`瑞士风格原型`](../design/swiss-blog-prototype/README.md) 实施公开文章列表和详情的桌面与手机布局。
- 保留真实文章数据、分类筛选、分页、标签、Markdown、代码、Mermaid、公式、文章大纲、背景音乐与加载/失败/空状态。
- 使用现有 React、TypeScript 与 CSS，不新增运行时依赖。
- 完成后提交功能分支，通过 Pull Request 合并到 `main`，经现有 CI/CD 部署并验证。

## 非目标

- 不修改管理端页面、后端 API、数据库 Schema、部署脚本或内容模型。
- 不新增搜索、评论、关于页、阅读时长或新的文章字段。
- 不改变背景音乐的播放逻辑，只使现有控件适配新视觉。

## 故事与验收标准

### 故事 1：公开前台视觉重构

- Given 访客打开文章列表，When 浏览桌面或 320px 及以上的手机页面，Then 按原型看到清晰的站点标识、主标题、分类、文章标题、时间和标签，页面不出现整体横向滚动。
- Given 访客按分类筛选或翻页，When 文章列表更新，Then URL 参数、当前分类和分页行为保持原有语义；空列表、加载失败与加载中仍有可读反馈。
- Given 访客打开文章详情，When 阅读长文或技术内容，Then 标题、元信息、Markdown、代码、图表、公式和大纲仍可用；窄屏代码块独立横向滚动。
- Given 访客在前台列表与详情之间切换，When 使用背景音乐控制，Then 播放状态和可访问名称保持原有行为。
- Given 访客遇到不存在的文章或请求失败，Then 仍看到对应的 404 或失败提示，并可返回文章列表。

### 故事 2：合并与部署

- Given 功能分支的 `make check` 和 Pull Request `check` 均通过，When 合并到受保护的 `main`，Then Release 使用该合并提交构建与部署镜像。
- Given 生产 Environment 批准部署，When 发布完成，Then Web/API 健康检查成功，前台列表与文章详情能正常读取；失败则按现有发布流程回滚。

## 风险与依赖

- 当前全局 CSS 同时服务公开页与管理端。新视觉必须限定在公开页，避免改变管理端样式。
- 示例原型没有真实 API 的加载、空状态和分页；实施时保留现有行为并检查其在新布局中的位置。
- 生产部署依赖 GitHub `production` Environment 的人工批准；不得绕过分支保护、CI 或发布准入。
- 本次没有数据迁移、鉴权或新依赖风险。
