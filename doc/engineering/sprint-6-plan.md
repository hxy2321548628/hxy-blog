# Sprint 6 开发计划

- 日期：2026-10-10
- 状态：本地实现与验证完成，待发布后验收
- Sprint 目标：让博主上传 BMP、GIF 并插入文章，让访客在文章中查看，GIF 保留动画。

## 目标与范围

- 目标用户：在管理端编辑文章的博主，以及阅读文章的访客。
- 在现有 JPG、PNG、WebP 基础上，增加 BMP、GIF 两种上传格式；文件选择、拖放和服务端上传入口保持一致。
- 保留原文件上传方式，使 GIF 动画在管理端预览和文章详情中播放。
- 服务端继续按内容识别格式、校验完整图片和尺寸；不信任文件名或浏览器上报的 MIME 类型。
- 沿用单文件 10 MiB、单边 8192 像素、总像素 2000 万及管理员鉴权限制。
- GIF 最多 1000 帧，所有帧矩形累计最多 1 亿像素，避免压缩动图耗尽 2C2G 主机内存。
- 通过带 up/down 的迁移放宽 `media_assets` 的 MIME 类型约束，既有媒体数据不改写。

## 非目标

- 不增加 AVIF、TIFF、HEIC、SVG、视频或任意附件上传。
- 不做图片转换、压缩、裁剪、动图转码、缩略图或批量媒体管理。
- 不改变文章内容模型、媒体 URL、COS 桶或上传 API 的请求和响应结构。
- 不实施 Sprint 5 尚待记录的生产内容人工验收。

## 故事与验收标准

### 故事 1：BMP、GIF 上传与展示

- Given 博主选择或拖放有效 BMP、GIF，When 填写替代文本并上传，Then 上传成功、返回稳定媒体 URL 和正确的 MIME 类型、尺寸，且插入文章的 Markdown 图片引用。
- Given 博主上传多帧 GIF，When 在管理端查看上传结果或访客打开已发布文章，Then 图片可见且动画保留；BMP 在同一位置可正常显示。
- Given 图片内容与扩展名或浏览器 MIME 类型不一致，When 上传，Then 服务端以内容为准生成对象扩展名、MIME 类型和元数据。
- Given BMP、GIF 文件损坏、格式不支持、超过大小或尺寸限制，When 上传，Then 服务端拒绝且不产生媒体元数据或 COS 对象；管理端显示明确反馈。
- Given GIF 超过帧数或累积像素预算，When 上传，Then 服务端在完整解码前拒绝。
- Given 现有 JPG、PNG、WebP 图片，When 上传和展示，Then 既有行为与限制保持可用。

## 已确认的假设

- “BMP 和 GIF”指常见的、可由当前 Go 图像解码依赖解析的文件；无法解析的 BMP 变体按损坏或不支持处理。
- GIF 应保留原始动画；静态首帧预览不满足本故事。
- “展示”指现有管理端上传结果和文章详情的图片展示，不新增独立媒体浏览页。

## 风险与依赖

- 现有 ADR-0002 将 GIF 排除在 MVP 外；本 Sprint 是 MVP 之后的格式扩展，实施时需同步记录决策范围变化。
- GIF 可能包含大量帧。完整校验必须限制解码资源，防止 2C2G 主机因小文件产生过量内存占用；损坏的后续帧不能被当作有效动画上传。
- BMP 通常不压缩，现有 10 MiB 上限可能使较大的 BMP 无法上传；本次不放宽该限制。
- 数据库现有 `chk_media_assets_mime_type` 仅允许三种 MIME 类型；需要可回滚迁移。回滚前若已有 BMP/GIF 数据，必须先处理不兼容数据，不能静默丢失媒体记录或对象。
- 优先复用 Go 标准库与已有 `golang.org/x/image` 依赖；若实现需要新增依赖，先说明必要性、许可证和资源成本。

## 验证命令与检查

- 先运行新增的失败测试，再实现最小改动并验证通过。
- `cd src/backend && go test ./internal/media ./cmd/api`
- `cd src/backend && go test -tags=integration ./internal/migrations`（需要已确认的本地 MySQL）
- `npm --prefix src/web test`
- `make check`
- 人工用 BMP 和多帧 GIF 完成管理端上传、文章发布及浏览器展示检查；核对 GIF 动画、稳定 URL 和替代文本。

## 本地验证记录

- 新增格式的后端测试先失败，实施后通过：BMP/GIF 内容识别、损坏的 GIF 后续帧、GIF 帧数预算和原始动图字节上传。
- 前端格式预检与文章 Markdown 图片标签测试通过；`make check` 通过，包含 Go、React、ESLint、TypeScript 和生产构建。
- 在独立临时 MySQL 中完成 Goose `up → 集成测试 → down → up`，确认第 6 版约束允许 BMP/GIF、拒绝 SVG，回退后版本为 5 且旧白名单恢复；临时容器和卷已清理。
- 无头 Chrome 通过本地测试页读取 BMP 与 GIF，二者自然尺寸均为 80×80；多帧动画由后端测试确认原文件字节不变。尚未在管理端通过隔离 COS 或生产 COS 完成实际上传与动画播放的人工验收。
