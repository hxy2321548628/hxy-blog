# 产品 Backlog

## 产品目标

让访客能快速阅读博主的文章，让博主能安全、稳定地编辑和发布内容。

## Sprint 0：工程基线

Sprint 目标：建立一条人与 AI 都能重复执行的开发闭环。

- [x] 建立 AI 项目约束、代码和 Git 规范。
- [x] 建立 Go + React 行走骨架和健康检查。
- [x] 使用现有镜像建立 MySQL 本地环境。
- [x] 建立统一本地质量命令和 PR CI。
- [x] 建立 Issue/PR 模板。
- [x] 配置远程 `main` 分支保护。
- [x] 用 ADR 固化完整技术选型并关闭实施前开放项。
- [x] 建立合并后的构建、部署、健康检查和回滚流水线。
- [x] 在 `ssh tencent` 服务器完成部署与回滚演练。

Sprint 0 已于 2026-09-30 完成验收，证据见 [`Sprint 0 验收记录`](../engineering/sprint-0-acceptance.md)。ICP备案、正式 DNS/TLS 和公网开放属于后续上线门禁，不阻塞 Sprint 1 开发。

## Sprint 1：最小可发布内容链路

Sprint 目标：访客可查看已发布的文章，博主可在受保护的入口创建并发布文章。

1. [x] 初始数据库模型与可回滚迁移。
2. [x] 访客查看已发布文章列表。
3. [x] 访客通过稳定 slug 查看文章详情。
4. [x] 单管理员安全登录。
5. [x] 管理员创建草稿并发布文章。
6. [x] 管理员上传图片并插入文章。

Sprint 1 已于 2026-10-01 完成验收，证据见 [`Sprint 1 验收记录`](../engineering/sprint-1-acceptance.md)。

## Sprint 2：内容管理与阅读体验

Sprint 目标：博主可维护文章全生命周期及分类标签，访客可按分类浏览并获得适合技术文章的阅读体验。

1. [x] 管理员创建、编辑和删除文章，已发布文章也可编辑。
2. [x] 每篇文章属于一个分类并可关联多个标签，前台支持分类展示和筛选。
3. [x] 技术文章支持带行号的按语言语法高亮代码块、Mermaid 图表、数学公式和可点击大纲。
4. [x] Header 中暂时移除尚无页面的“关于”入口。

Sprint 2 已于 2026-10-02 完成验收，详细范围见 [`Sprint 2 开发计划`](../engineering/sprint-2-plan.md)，证据见 [`Sprint 2 验收记录`](../engineering/sprint-2-acceptance.md)。

## Sprint 3：沉浸式阅读氛围

Sprint 目标：访客浏览博客前台时可伴随固定背景音乐阅读，并能随时暂停或继续播放。

1. [x] 前台页面默认尝试以 5% 音量循环播放背景音乐；若被浏览器拦截，则在访客首次点击页面时开始播放，并提供始终可用的暂停/继续控制。

详细范围见 [`Sprint 3 开发计划`](../engineering/sprint-3-plan.md)。

Sprint 3 已于 2026-10-02 完成验收，证据见 [`Sprint 3 验收记录`](../engineering/sprint-3-acceptance.md)。

## Sprint 4：博客前台视觉原型

Sprint 目标：为现有博客前台提出适合文章浏览和长文阅读的瑞士风格视觉方案，先以可评审原型确认方向。

1. [x] 为文章列表与文章详情制作桌面和手机布局原型，展示现有的分类、标签、文章大纲和技术内容。

详细范围、原型交付和验收记录见 [`Sprint 4 原型计划`](../engineering/sprint-4-plan.md)。原型已由用户确认，生产前端页面由 Sprint 5 实施。

## Sprint 5：按瑞士风格原型重构博客前台

Sprint 目标：将已确认的文章列表与详情原型应用到真实前台，保持现有阅读与浏览能力，并通过现有流水线发布。

1. [x] 按原型重构公开文章列表和详情的桌面、手机布局，保留分类、分页、Markdown、大纲、背景音乐与错误状态。
2. [x] 前端检查通过后经 Pull Request 合并到 `main`，由现有发布流水线部署并验证 Web/API 健康状态。
3. [x] 在生产环境人工验证真实文章列表、分类和文章详情的读取与展示，记录验收结果。

范围和验收记录见 [`Sprint 5 开发计划`](../engineering/sprint-5-plan.md)。PR #20 已合并，Release 已部署；用户于 2026-10-10 确认生产环境的真实文章列表、分类和文章详情人工验收通过。

## 暂不进入 MVP

多用户、评论、搜索、独立媒体库、图片编辑/转换、RSS、统计仪表盘、微服务和 Kubernetes。

## Sprint 6：扩展文章图片格式

Sprint 目标：博主可上传 BMP 和 GIF 图片并插入文章，访客可在文章中查看图片，GIF 保留动画。

1. [x] 管理端允许选择和拖放 BMP、GIF，继续支持 JPG、PNG、WebP，并沿用现有大小、替代文本与上传反馈规则。
2. [x] 后端按文件内容校验 BMP、GIF，保存正确的 MIME 类型和扩展名；通过可回滚迁移允许新 MIME 类型入库。
3. [x] 上传后可在管理端预览和文章详情中展示 BMP、GIF，GIF 保留动画。

范围、非目标、风险和本地验证记录见 [`Sprint 6 开发计划`](../engineering/sprint-6-plan.md)。用户已确认只新增 BMP 和 GIF，GIF 保留动画；生产上传与展示需发布后验收。

## Sprint 7：统一 Task 命令与 CI/CD

Sprint 目标：以 Task 统一本地和 CI 的构建、检查入口，并使 CI/CD 符合新规范且保留现有发布安全边界。

1. [x] 以根目录 `Taskfile.yml` 替换 Makefile，覆盖现有开发、检查、容器和隔离媒体测试命令。
2. [x] 将 CI 的本地可运行验证逻辑收敛到 Task 或脚本，固定 Task 版本和第三方 Action 完整 SHA，保持 `check` 状态名称。
3. [x] 调整发布流程的本地构建入口和制品元数据记录，保持已验证提交、镜像 Digest、生产审批与回退链路。

范围、非目标、风险和本地验证结果见 [`Sprint 7 开发计划`](../engineering/sprint-7-plan.md)；GitHub PR 与生产发布行为尚待远程验证。
